## Тестируемый этап — MARK Audio 0.7.27

### Отдельный пользовательский Android OAuth-клиент MARK Audio Music

Владелец зарегистрировал новое приложение **«Для авторизации пользователей»** на Android с package name `com.markmusic.player`, релизным SHA-256 и разрешением `music:api-public`. Публичный Client ID `a74b75bb16a04004bed54af5fa52b574` добавлен в отдельную конфигурацию приложения, **Client secret не используется**.

В версии 0.7.27:
- Новый пользовательский Music OAuth запускается официальным Yandex LoginSDK 3.3.0 с `YandexAuthLoginOptions(clientId = ...)`, без изменения основного LoginSDK Client ID в Gradle. Отдельные обратные ссылки регистрируются через AndroidManifest для нового клиента.
- Результат токена сверяется по официальному `login.yandex.ru/info`: должны совпасть **Client ID нового приложения и ID уже подключённого Яндекс-аккаунта**. Необходимость повторного ввода пароля/кода отсутствует, кроме действий в интерфейсе Яндекса.
- Новый токен сохраняется только в Android Keystore AES-GCM под отдельным ключом `user_token`; старый токен Music API и Яндекс ID не заменяются и не удаляются.
- По явному нажатию отдельная диагностическая кнопка выполняет **один** HTTPS GET к известному из сообщества `api.music.yandex.net/account/status`, показывает обезличенный HTTP-результат и никогда не обращается к потокам или плейлистам. Метод не подтверждён как официальный контракт для стороннего приложения.
- Unit-тесты проверяют корректный новый Client ID, совпадение UID и отклонение чужого OAuth-клиента.

**Осталось:** зелёный CI, подписанный релиз 0.7.27 и практическая проверка на Huawei Pura 80 Ultra. 200 на `/account/status` сам по себе не даёт права на licensed streaming, а 403 требует решения со стороны Яндекса, а не обхода. Рабочий релиз 0.7.26 остаётся доступен до проверки.

## Тестируемый этап — MARK Audio 0.7.26

### Повторный аудит OAuth Яндекс Музыки

В 0.7.25 Yandex ID LoginSDK и Music OAuth проверялись независимо: сверялся `client_id` второго приложения, но **не совпадение пользовательских ID**. В браузере Yandex OAuth пользователь мог выбрать иной Яндекс ID, чем в установленном LoginSDK. Эта гипотеза не проверялась на Huawei.

В 0.7.26 кнопка «Проверить OAuth-токен» получает только уже доступный по официальному `login.yandex.ru/info` ID владельца Music OAuth-токена и **сравнивает в памяти** с `YandexAccount.userId` из LoginSDK. Отображается один из результатов: аккаунты совпадают; аккаунты отличаются; сравнение невозможно, если LoginSDK отключён; либо прежние ошибки проверки. Логины, UID, токены и полные ответы не выводятся в экран или логи. Повторный вход и создание токена для этого теста не нужны.

Официальные данные, которые важно учесть: Яндекс OAuth различает приложения «Для авторизации пользователей» и «Для доступа к API» (последние работают с данными разработчика); тип нельзя поменять после регистрации. Тип второго клиента **пока не проверен непосредственно в кабинете**. Регистрация права `music:api-public` не доказывает поддержку каталога и стриминга, а успешный `login.yandex.ru/info` — только личность/Client ID. Отдельный эксперимент `api.music.yandex.net/account/status` вернул HTTP 403. Эти факты не позволяют заключить, что все возможные разрешённые операции недоступны.

Следующее подтверждение владельца: проверить **тип второго OAuth-клиента в кабинете** и результат новой кнопки. Для сравнения типов приложений: https://yandex.ru/dev/id/doc/ru/register-client . Тесты и подписанный APK не заменяют проверки Huawei.

### 0.7.25 — оптимизация плавности прокрутки (требуется проверка Huawei)

**Результат владельца 21.11.2026:** MARK Audio 0.7.24 на Huawei Pura 80 Ultra показал **HTTP 403** для `api.music.yandex.net/account/status`. Официальный Яндекс ID и проверка его OAuth-токена при этом успешно работают. 403 означает отказ на конкретном Music API endpoint и не должен трактоваться как необходимость заново вводить код. Лицензированные потоки/каталог **не открыты**.

Владелец также сообщил о заметно рывковой прокрутке интерфейса. Анализ Compose выявил затратные элементы: вся вкладка Яндекс Музыки прокручивалась как один большой `Column(verticalScroll)` с двумя полноразмерными `NeonGlass`; статические информационные карточки получали `graphicsLayer` и вращение при каждом обновлении датчика наклона (до 25 Гц), глубокие тени и пересоздание градиентного шейдера при отрисовке.

Исправлено:

- Экран Яндекс Музыки переведён на `LazyColumn` с тремя стабильными ключами (заголовок, Яндекс ID, Music API): Compose измеряет/рисует нужные секции без полной подготовки заэкранного контента.
- Статические `NeonGlass` не получают сенсорный 3D-слой, а тень этих панелей облегчена; нажимаемые кнопки по-прежнему сохраняют свою анимацию, градиенты и контур стекла.
- Блик стекла рассчитывается через `drawWithCache`, чтобы не создавать новый шейдер на каждом кадре; правило разделения карточек закрыто unit-тестами.
- В локальной медиатеке группировка и сортировка альбомов/исполнителей/папок кешируются через `remember(songs, category)`, а ленивые ряды имеют уникальные стабильные ключи.

В этой версии **не меняются** Yandex LoginSDK, OAuth/Keystore, HTTP-запросы, Media3, визуализаторы и Suno. Контроль качества: GitHub Actions (Gradle tests / lint / APK), signed release с закреплённым ключом и **ручная проверка плавности на Huawei**. Без реального GPU-профилирования улучшение FPS нельзя считать измеренным.

### 0.7.24 — различаем ответы Music API 401, 403 и 429

**Проверка владельца на Huawei 21.11.2026:** в 0.7.23 экспериментальный запрос статуса аккаунта через `api.music.yandex.net/account/status` вернул отказ, но приложение скрывало точный статус, показывая «401/403». При этом официальный Яндекс ID `login.yandex.ru/info` ранее подтвердил Music OAuth-токен нашего отдельного зарегистрированного клиента.

Теперь отдельные результаты: **401** — запрос не авторизован токеном на конкретном сервере; **403** — доступ к методу запрещён (возможны ограничения прав или клиента); **429** — частотное ограничение. Прочие HTTP/сетевые проблемы по-прежнему показываются без раскрытия серверного ответа. Токен и сведения об аккаунте не сохраняются в логи или UI. Не меняем `Authorization: OAuth` на неизвестный вариант, не запрашиваем чужие токены и не пытаемся обходить ограничения сервиса.

**Важно:** Яндекс ID и Music API — разные серверы, поэтому успешная проверка у одного из них не даёт гарантии доступа к другому. Нет подтверждённой официальной спецификации каталогов или аудиопотоков для стороннего Android-плеера. Повторять неподтверждённый запрос много раз не нужно.

### 0.7.23 — экспериментальная проверка доступа к серверу Яндекс Музыки (в тестировании)

На Huawei Pura 80 Ultra владелец проверил 0.7.22: официальный `login.yandex.ru/info` подтвердил действительность OAuth-токена нашего второго Music API-клиента. Это не является подтверждением доступа к самому сервису Яндекс Музыки.

**Эксперимент по отдельному нажатию:** на вкладке Яндекс Музыки после подключения есть кнопка «Экспериментально проверить Music API». Она делает один read-only HTTPS-запрос `GET https://api.music.yandex.net/account/status` с **уже сохранённым** Music API OAuth-токеном. Endpoint документирован **только сообществом**, например https://github.com/MarshalX/yandex-music-api ; официальной поддерживаемой спецификации для независимого Android-клиента не обнаружено. Токен отправляется исключительно серверу Яндекса, запрос не следует редиректам, ответ с данными аккаунта не отображается, не записывается и не передаётся третьим сторонам. Приложение показывает только один из обезличенных результатов: ответ сервиса, отклонение 401/403, неожиданный формат или временная недоступность.

**Никаких запросов к плейлистам, лайкам, медиафайлам, потокам или DRM нет.** Результат `/account/status` служит только проверкой совместимости именно этого запроса и **не подтверждает** ни права на лицензионное воспроизведение, ни работоспособность других методов. Рабочий вход Яндекс ID и локальный Media3-плеер не затронуты. Для 0.7.23 необходимы CI и фактическая проверка на Huawei.

### 0.7.22 — проверка сохранённого Music API OAuth-токена (в тестировании)

Владелец подтвердил на Huawei Pura 80 Ultra получение и сохранение отдельного OAuth-токена второго клиента с заявленным scope `music:api-public` (21.11.2026). Этот результат подтверждает удачный обмен кода и отображение состояния MARK Audio, но не проверяет доступ к музыкальному каталогу или аудиопотокам.

На экране Яндекс Музыки после подключения появился пункт **«Проверить OAuth-токен»**. При нажатии приложение передаёт **уже сохранённый** токен только в HTTP-заголовке Authorization официального HTTPS-запроса `https://login.yandex.ru/info?format=json` и сверяет возврат `client_id` со вторым OAuth-клиентом. Проверка не выводит логин, ID пользователя, токен или содержимое ответа; временные ошибки сети не уничтожают токен. Документация Яндекса разрешает вызов этого API с токенами других сервисов: https://yandex.ru/dev/id/doc/ru/user-information .

**Это проверка действительности и принадлежности токена, а не права на каталоги или воспроизведение.** В приложении не активированы сетевые каталоги, playlists или stream endpoints; локальный Media3 и Яндекс ID остаются без изменений. Проверка на Huawei нового действия потребуется после тестового релиза.

### 0.7.21 — исправление поля OAuth-кода Яндекс Музыки (проверяется)

В 0.7.20 было ошибочно задано ограничение **ровно 7 цифр**; на реальном Huawei 21.11.2026 Яндекс фактически показал **16-символьный буквенно-цифровой код** на странице verification_code. В 0.7.21 поле допускает и 16 латинских букв/цифр, и семь цифр, предлагает буквенную клавиатуру, проверяет длину, сохраняет регистр и скрывает ввод по умолчанию. Код остаётся только в оперативной памяти UI, а в network POST отправляется без ручных преобразований; сервер Яндекса окончательно проверяет его действительность. Скриншот и код владельца не копируются в GitHub.

Важно: официальная справка Яндекса для ошибки bad_verification_code всё ещё говорит о 7 цифрах, и тест на устройстве не завершён до ответа OAuth-сервера. Если сервер отвергнет буквенный код, исправим сам способ выдачи/обмена, а не будем менять регистр или подставлять посторонние токены.

### 0.7.20 — подключение второго OAuth-клиента Яндекс Музыки (история)

1. Открой **Медиатека → Яндекс Музыка → Получить код Яндекс Музыки**. Откроется официальный сайт Яндекс OAuth с разрешением Music API, зарегистрированным владельцем.
2. Подтверди разрешение в Яндексе. На проверенном Huawei Яндекс показал **16-символьный код из латинских букв и цифр**, что прямо соответствует определению «Код для получения токена» в официальном глоссарии https://yandex.ru/dev/id/doc/ru/concepts/glossary . В одной из таблиц ошибок по-прежнему упоминаются семь цифр. 0.7.21 принимает оба формата. Код действует 10 минут.
3. Вернись в MARK Audio и введи код **только** в поле приложения, не отправляй его в чат и никуда больше. MARK Audio обменяет его через официальный OAuth HTTPS + PKCE без Client secret.
4. Подключение Music API отобразится отдельно от Яндекс ID. Токен шифруется под самостоятельным ключом Android Keystore; «Отключить Music API» удаляет локальный токен, не затрагивая Яндекс ID. Для отзыва на стороне Яндекса используй кабинет OAuth.
5. **Важно:** подключение проверяет только выдачу OAuth-токена с Music API scope. В этой версии нет запросов к недокументированным музыкальным endpoints, синхронизации плейлистов или стриминга. Текущая Media3-библиотека, Suno и визуализации остаются рабочими.

Документация протокола: https://yandex.ru/dev/id/doc/ru/codes/screen-code ; https://yandex.ru/dev/id/doc/ru/register-api . Фактическая проверка нового кода на Huawei и CI отмечается отдельно.

## MARK Audio 0.7.11 — 8 музыкальных аппаратов, настоящие таймеры и VU-индикаторы

К уже доступным виниловому проигрывателю, «Маяку-203» и «Весне-202-1» добавлены пять отдельных фотоаппаратов:
CD-проигрыватель с лазерной головкой, MiniDisc, профессиональный DAT, ламповый радиоприёмник и Jukebox.

**Навигация:** свайпы влево/вправо с прежней анимацией 370 мс, циклический переход по восьми аппаратам и сохранение выбора при перезапуске.

**Фотографическое оформление:** пять оригинальных сгенерированных для MARK AUDIO художественных фотоконцептов из переписки пользователя. Они хранятся в репозитории как Base64-кодированные WebP с закреплёнными SHA-256, автоматически помещаются в APK в ходе сборки и **не загружаются из сети во время работы**. Их нельзя представлять как фотографии подлинных моделей производителя.

**Механика:** диск CD с отдельной неподвижной лазерной головкой, вращающийся MiniDisc, два DAT-шпинделя с изменением скоростей по намотке, виниловая пластинка в механизме Jukebox и подсветка лампового радио. Анимация синхронизирована с кадрами без пропуска кадров короче 9 мс, останавливается при паузе и в фоне.

**Функциональные дисплеи и индикаторы:**
- Таймеры CD, MiniDisc и DAT отображают **реальную позицию воспроизведения Media3**, MiniDisc дополнительно показывает общую длительность и название композиции.
- Play подсвечивается при воспроизведении, Pause — при приостановке; на аппаратах без собственных кнопок Play/Pause подсветка соответствует устройству (радиолампы и Jukebox).
- Стереоиндикаторы MiniDisc и DAT вычисляют **реальные RMS уровни левого и правого PCM-канала** через проходной Media3 TeeAudioProcessor без RECORD_AUDIO и без Android Visualizer API. Частота обновления ограничена ~30 Гц, замеры отключаются, когда аппарат скрыт или плеер на паузе. В радио и Jukebox яркость ламп зависит от той же измеренной энергии музыки. Это НЕ синтетический эквалайзер, а динамический индикатор уровня звука.
- Поскольку напрямую декодированный PCM может быть недоступен для passthrough/offload, индикаторы в этом случае честно показывают отсутствие данных, а не случайный сигнал. Оригинальные аудиофайлы никак не изменяются.

**Важное уточнение:** после технической проверки APK необходимо протестировать вид анимаций, расположение подсветки и совместимость аудиотракта с Huawei Pura 80 Ultra. Метрики 120 FPS и отсутствие нагрева нельзя подтвердить на GitHub Actions.

## MARK Audio 0.7.12 — танцующая 3D-фигурка Марка

По обратной связи после 0.7.11 **полностью удалены** четыре визуализации: CD, MiniDisc, DAT и Jukebox. Их Kotlin-реализации и четыре изображения не включаются в APK. Режимы: винил, «Маяк-203», «Весна-202-1», ламповое радио, и **MARK 3D**.

**Новый персонаж** — оригинальный фирменный стилизованный робот MARK AUDIO с сине-фиолетовым корпусом, гарнитурой, светящимися глазами и объёмной эмблемой «M» на груди. Это **реальная 3D-сцена OpenGL ES 2.0**, а не вращение плоского рендера: отдельные объёмные меши для головы, корпуса, шарнирных рук и ног; перспективная камера, освещение, глубина, металлические блики и сцена-подиум. Движения плеч, локтей, запястий, коленей, стоп и головы рассчитываются покадрово.

**Музыкальный ритм** поступает из существующего Media3 TeeAudioProcessor без микрофона. Лёгкий детектор анализирует низкочастотную энергию декодированного PCM (однополюсный НЧ-фильтр на 150 Гц), сравнивает её с адаптивным фоном, выявляет нарастающие транзиенты и выдаёт события с минимальным интервалом 190 мс. Степень движения зависит от фактических RMS уровней и событий долей, с плавным затуханием после удара. **Танец не генерирует случайные удары**. При паузе персонаж возвращается к спокойной позе; в фоне OpenGL-сцена приостанавливается.

**Совместимость:** OpenGL ES 2.0 — стандартная часть Android, новые библиотеки, сервисы Google, INTERNET и RECORD_AUDIO не нужны. Радио по-прежнему реагирует свечением ламп на настоящий PCM. При недоступном PCM (например, специфический аппаратный аудиотракт) персонаж не будет выдавать ложные удары, а останется почти неподвижным.

**Навигация:** свайп по пяти визуализациям с прежней анимацией; выбор сохраняется. Если раньше был выбран CD, MiniDisc, DAT или Jukebox, предпочтение автоматически переводится на MARK 3D без сброса остальных настроек.

**Ограничения:** Это новая оригинальная 3D-интерпретация персонажа, пока без отдельной утверждённой модели талисмана. Настоящий FPS, термическую нагрузку, реакцию разных записей и качество трёхмерного дизайна необходимо проверить на Huawei Pura 80 Ultra; GitHub CI подтверждает компиляцию и тесты, но не работу реального GPU.
