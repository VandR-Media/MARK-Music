# MARK Audio 0.7.17 — Яндекс ID: безопасный вход

## Назначение

Внутри MARK Audio теперь предусмотрен **отдельный вход в Яндекс ID**, чтобы подтвердить владельца аккаунта для будущей работы с собственным Music API. Это не обещает потоковое воспроизведение Яндекс Музыки: доступ к музыкальному каталогу и лицензированным потокам по-прежнему требует отдельного разрешённого интерфейса.

Официальная документация:
- https://yandex.ru/dev/id/doc/ru/register-auth
- https://yandex.ru/dev/id/doc/ru/codes/code-url
- https://yandex.ru/dev/id/doc/ru/user-information

## Что нужно владельцу (не отправлять пароли, токены или Client secret)

1. На [странице регистрации](https://oauth.yandex.ru/client/new/id/) создать собственное приложение MARK Audio.
2. Зарегистрировать Redirect URI **в точности**: `markaudio://oauth/yandex`. Настроить разрешение **API Яндекс ID / login:info**. Если Яндекс откажет в таком Redirect URI или потребует подтверждение приложения, **не использовать чужой Client ID**, а зафиксировать отказ и согласовать корректный адрес / официальный LoginSDK.
3. В MARK Audio → Медиатека → Яндекс Музыка → «Настроить вход Яндекс ID» вставить только публичный **Client ID** этого приложения. Client secret не нужен при PKCE.
4. Нажать «Войти». Авторизация откроется во внешнем браузере, после разрешения доступа браузер вернёт управление приложению.
5. После подтверждения профиля в карточке отобразится логин. Для выхода — «Отключить Яндекс ID».

**Только Яндекс ID:** пользовательские файлы, сохранённые Suno MP3/WAV, эквалайзер, очередь и визуализаторы продолжают работать без аккаунта. Даже если вход успешен, MARK Audio не получает автоматического доступа к аудиопотокам Яндекс Музыки.

## Ошибка 400: redirect_uri / Callback URL не совпадает

Проверено по скриншоту пользователя 20 ноября 2026: Яндекс OAuth отклонил запрос **до авторизации** с сообщением `redirect_uri не совпадает с Callback URL, указанным при регистрации приложения`.

**Текущий Redirect URI MARK Audio 0.7.17: `markaudio://oauth/yandex`**.

Причина — несовпадение Redirect URI для выбранного **Client ID**, а не ошибка подписанного APK. Яндекс сверяет `scheme`, `host`, порт (если есть) и `path`, а параметры запроса и fragment не обязаны совпадать.

Что проверить:

1. Открой https://oauth.yandex.ru/ и выбери **то же OAuth-приложение**, чей `Client ID` введён в MARK Audio. Не отправляй пароли, токены, секреты или URL запроса авторизации со значениями `state` другим людям.
2. Тип должен быть **«Для авторизации пользователей»**. Тип **«Для доступа к API»** имеет фиксированный `redirect_uri` `https://oauth.yandex.ru/verification_code`, он не подходит для встроенного возврата в MARK Audio. Тип приложения нельзя изменить после регистрации — создавай правильный тип заново, если выбран неверный.
3. В платформе **«Веб-сервисы» → «Redirect URI»** проверь точное совпадение с `markaudio://oauth/yandex` (без пробела и без дополнительного слеша в конце). Добавь адрес, если Яндекс разрешает его, и сохрани настройки. Только при том же Client ID получится вернуться в MARK Audio.
4. Открой «Медиатека» → «Яндекс Музыка» → «Настроить вход Яндекс ID» и проверь Client ID. Повтори авторизацию новым запросом.
5. Если веб-интерфейс Яндекс OAuth не разрешает собственную схему `markaudio://`, **не вводи вместо неё случайный HTTPS-адрес**: текущий AndroidManifest не умеет его принимать. В этом случае требуется отдельная доработка приложения (LoginSDK или проверенный HTTPS App Link) после подтверждения поддерживаемого сценария.

Документация Яндекса:
- https://yandex.ru/dev/id/doc/ru/register-auth — типы, платформы и сравнение Redirect URI;
- https://yandex.ru/dev/id/doc/ru/register-api — фиксированный адрес приложений для доступа к API;
- https://yandex.ru/dev/id/doc/ru/codes/code-url — передача `redirect_uri` в авторизационном запросе.

**Важно:** переустановка APK не изменит Callback URL, сохранённый в Яндекс OAuth. Исправить данные OAuth-приложения может только владелец соответствующего аккаунта Яндекса. Даже после успешного входа `login:info` не даёт MARK Audio доступ к потокам Яндекс Музыки.

## Реализация

- Official OAuth Authorization Code + PKCE/S256. Random `code_verifier`, `state`, строгая проверка callback URI, подтверждение срока жизни и одноразового запроса.
- Обмен кода: POST `https://oauth.yandex.ru/token`, тело `grant_type=authorization_code`, `code`, `client_id`, `code_verifier`. Пароль пользователя и `client_secret` не нужны.
- Проверка профиля: GET `https://login.yandex.ru/info?format=json` с заголовком `Authorization: OAuth <token>` (никогда не помещать токен в URL).
- Шифрование OAuth-токена и отложенного запроса через Android Keystore AES-256/GCM. `android:allowBackup=false`. Потерянный или повреждённый ключ — сброс связанного подключения.
- Короткие HTTPS timeout, запрет HTTP cleartext, ограничения на чтение ответов, отсутствие логирования токенов.
- Новое разрешение только `android.permission.INTERNET`; статический аудиоанализатор не использует микрофон, камера/SMS/контакты по-прежнему запрещены проверкой релиза.
- Локальная кнопка «Отключить» удаляет токен из памяти приложения, но не отзываeт его на серверах Яндекса. Для полного отзыва — страница «Доступы к данным» Яндекс ID. Автоматическое обновление токенов пока не реализовано.
- Процесс возвращается в существующую Медиатеку; второй аудиодвижок не создаётся. Не зависит от Google Play Services.

## Проверки и ограничения

- Автоматические JVM unit-тесты построения POST-формы, отсутствия `client_secret`, корректного URL-кодирования и PKCE.
- CI проверяет компиляцию, unit-тесты, Android Lint, релизные разрешения, подпись.
- **Вход в живой аккаунт не проверен**, потому что нет зарегистрированного Client ID проекта и согласованного права музыкального API. Не запрашивать Client secret в чате и не коммитить его в GitHub.
- После регистрации может потребоваться выбор официального Yandex LoginSDK или проверенного HTTPS App Link, если нестандартный Redirect URI не поддерживается настройками приложения.
