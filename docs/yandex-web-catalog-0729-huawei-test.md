# MARK Audio 0.7.29 — самостоятельный каталог + официальный веб-режим

## Что реализовано

- **Новый opt-in экран** «Яндекс Музыка · веб-режим» открывает только официальный `https://music.yandex.ru/` внутри отдельного Android WebView. Кнопка «Браузер» открывает этот же сайт через внешнее приложение.
- WebView включён только по нажатию пользователем; основной Яндекс ID и ранее полученные OAuth-токены MARK Audio не используются веб-экраном. Для сайта может потребоваться отдельный вход.
- Навигация ограничена HTTPS/официальными хостами Яндекса (системный браузер — для сторонних ссылок). Нет JS-инъекции, `addJavascriptInterface`, перехвата запросов, экспорта cookies, выдачи себя за официальный клиент, DRM-обхода.
- В UI сохранены все прежние авторизационные панели и локальный Media3.
- **MusicCatalogGateway** — строгие Kotlin-типы для треков/страниц/плейлистов, функции поиска, избранного, плейлистов и треков по ID, отдельные ошибки `NOT_CONFIGURED/AUTH_REQUIRED/FORBIDDEN/RATE_LIMITED/NO_NETWORK/INVALID_RESPONSE`. До подтверждения права доступа gateway возвращает явный `NOT_CONFIGURED`. Он **не скачивает чужой каталог и не подделывает результаты**.
- Добавлены unit-тесты типизированных ошибок, элементов каталога и HTTPS-политики навигации.

## Почему нет нативных треков пока

Несмотря на валидность OAuth с обоими scopes, запрос `/account/status` нашим клиентом на реальном Huawei дал HTTP 403 (#46). Сторонние реализации часто используют иные Client ID или скрытые механизмы выдачи аудио; они не дают нашему клиенту прав. Нативные read-only методы и Media3-стриминг включим только после подтверждённого разрешённого сервиса.

## Проверка на Huawei Pura 80 Ultra / EMUI 15

1. Установить подписанный APK 0.7.29 после того, как GitHub Actions подпишет его **тем же релизным сертификатом**. Обновление должно сохранить данные приложения.
2. Открыть **Медиатека → Яндекс Музыка → Эксперимент: открыть веб-плеер внутри MARK Audio**.
3. Проверить: отображается ли сайт, возможен ли вход, открываются ли поиск, избранное и плейлисты, воспроизводится ли трек **самим сайтом**.
4. Проверить: нажатие системной кнопки «Назад» и выход «Закрыть»; возвращение в MARK Audio; работа музыки после сворачивания/блокировки экрана и восстановления.
5. Если сайт или вход не поддерживаются в WebView, нажать «Браузер». Не пытаться копировать cookies из Chrome, не отправлять в чат код/токен/пароль.
6. Сообщить **только** обезличенную матрицу «страница/вход/каталог/музыка/фон», плюс скриншот ошибки без личных данных.

## Известные ограничения

- WebView — не Media3, управление песнями через общий MARK Audio плеер и визуализации пока невозможно.
- Звук/DRM/фоновое воспроизведение/авторизация могут зависеть от сервиса Яндекс Музыки и версии Huawei System WebView; аппаратная проверка обязательна.
- Данные о личном каталоге не синхронизируются из веб-страницы в MARK Audio.
- Официальные условия сайта могут запрещать/ограничивать встраивание; при отказе не обходить запрет.
