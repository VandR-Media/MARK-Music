# MARK Audio — что реально известно о `music:major-public-api` (22.11.2026)

## Вердикт

**Не доказано, что OAuth scope `music:major-public-api` открывает личную медиатеку, плейлисты, поиск или музыкальные потоки. Не добавлять его в действующие OAuth-клиенты MARK Audio без опубликованной спецификации или ответа Яндекса.**

В Яндекс OAuth разрешение называется **«Доступ к Music Major API»** и имеет **точный идентификатор `music:major-public-api`** (не `musicmajor-public-api`). Владелец подтвердил экраном настроек его сохранение вместе с `music:api-public` у **отдельного** API-type OAuth-приложения:

- Имя: `MARK Audio Music` (в кабинете несколько приложений с похожими названиями);
- Публичный Client ID: `017187c1377846eb80cedcd93cf3fd38`;
- В списке Яндекс OAuth статус **«Только API»**;
- Redirect: `https://oauth.yandex.ru/verification_code`.

Этот Client ID **НЕ равен** пользовательскому Android/LoginSDK-клиенту MARK Audio 0.7.27 (`a74b75bb16a04004bed54af5fa52b574`), который содержит только `music:api-public`. Добавление разрешения в API-type регистрацию не обновляет уже существующие токены другого OAuth-клиента.

Сохранённая конфигурация не доказывает выдачу отдельного нового токена, его фактический набор прав или разрешение конкретного Music endpoint.

## Проверка первоисточников

**Официальный Яндекс OAuth:**

1. Типы приложений для пользователей и для доступа к API отличаются; регистрация не позволяет потом сменить тип. Пользовательское приложение работает с данными пользователя, API-type предназначено для данных разработчика. https://yandex.ru/dev/id/doc/ru/register-client
2. Для API-type регистрация требует использовать **документацию соответствующего сервиса** для разрешений, API и способов подключения; фиксированный redirect `verification_code` соответствует API-type. https://yandex.ru/dev/id/doc/ru/register-api
3. Выдача токена с перечисленными в регистрации правами и возможное возвращение `scope` в ответе — это уровень **OAuth**, а не подтверждение музыкальным сервером. В ответе сервера поле `scope` может отсутствовать, если не произошло уменьшение набора разрешений. https://yandex.ru/dev/id/doc/ru/codes/screen-code-oauth

**Не найдено:** официального документа Яндекс Музыки с контрактом `Music Major API`, базовым URL, списком операций или указанием, что `music:major-public-api` разрешает `GET https://api.music.yandex.net/account/status` либо чтение/воспроизведение личных треков. Точный поиск по scope на публичном GitHub и поисковых системах тоже не дал первоисточника.

Отдельная **официальная Partner API Яндекс Музыки для артистов** существует (https://yandex.com/support/music-artists/ru/performers-and-copyright-holders/partners-api), но по найденной странице относится к партнёрским/промоматериалам и **не подтверждает**, что это та же служба, что `Music Major API`. Не смешивать эти интерфейсы без документации.

## НОВОЕ независимое свидетельство — Karin

В отличие от догадок, найден отдельный публичный разработческий проект **Karin** с подробно документированным экспериментом:

- [Регистрация собственного пользовательского OAuth-клиента](https://github.com/tracerxbrhd/karin/blob/main/docs/adr/0008-local-oauth-pkce-diagnostic.md): владелец выбрал **оба** музыкальных scope `music:api-public` и `music:major-public-api` плюс права `login`; подтверждались экран согласия, PKCE/authorization code, токен и связка Client ID/user ID в `login.yandex.ru/info`.
- [Реальная проверка 28.10.2026](https://github.com/tracerxbrhd/karin/issues/5#issuecomment-6470853664): два свежих запуска (с TUN и без TUN) дали **Music `/account/status` 403 и Music `/account/about` 403**. Причина отказа не известна; фактический предоставленный набор scope не был независимо подтверждён Music API. Запрос каталога не запускался.
- [Контролируемый тест заголовка](https://github.com/tracerxbrhd/karin/issues/5#issuecomment-6471631991): на **одном уже работающем токене другого клиента** Music `/account/status` отвечал 2xx **и с `X-Yandex-Music-Client`, и без него**. Это опровергает предположение, что такой заголовок *сам по себе всегда обязателен* для указанного метода. Но токен принадлежал *не* собственному OAuth-клиенту Karin; опыт не предоставляет права копировать чужую идентичность или обходить ограничения.
- [Технический аудит](https://github.com/tracerxbrhd/karin/blob/main/docs/API_FEASIBILITY.md) отдельно предупреждает: generic 403 не доказывает отсутствующий scope, подписку, географию или конкретный запрет. Сервисы могут иметь отдельную серверную политику.

**Применимость к MARK Audio:** на Huawei Pura 80 Ultra (MARK Audio 0.7.23/0.7.24/0.7.26/0.7.27) наши **два других** собственных OAuth-клиента с `music:api-public` прошли Яндекс ID, но Music `/account/status` возвращал HTTP 403. Karin — *отдельный*, независимый сценарий с двумя scope, указывающий, что добавление `music:major-public-api` не гарантирует устранения 403. Эти наблюдения нельзя объединять в якобы доказанный запрет для всех пользователей или всех endpoints.

## Какая гипотеза сейчас сильнее

| Предположение | Состояние |
| --- | --- |
| Неверный пользователь Яндекс ID | Исключено на Huawei 0.7.26: UID совпали |
| Неизвестный/недействительный OAuth-токен | Исключено **только на уровне** `login.yandex.ru/info`; Music API — отдельный сервис |
| Недостаточно выбрать user-type Android OAuth | Проверено на Huawei 0.7.27: всё равно 403 |
| Достаточно добавить Music Major permission | Не подтверждается: у Karin оба права, а музыкальный статус всё равно 403 |
| Обязателен заголовок `X-Yandex-Music-Client` | Не подтверждается: A/B-тест Karin показал 2xx без него на том же токене |
| Music endpoint имеет специальные правила допуска конкретных OAuth-клиентов | **Сильная гипотеза, но причины 403 не раскрыты** |
| Подписка, регион, ограничения сервиса | Не определены, generic HTTP 403 не объясняет причину |
| Music Major — API для правообладателей/лейблов | **Непроверенная гипотеза по названию**, не установленный факт |
