# MARK Audio — три источника музыки (итерация 1)

## Решение владельца проекта
В медиатеке нужны три вкладки: **«На устройстве»**, **«Яндекс Музыка»** и **«Suno»**.
Яндекс Музыка в перспективе должна воспроизводить музыку непосредственно в MARK Audio после авторизации владельца подписки. Suno нужен исключительно для прослушивания, без функций генерации.

## Что уже реализовано
- Переключение источника в медиатеке и сохранение выбора. Разрешения и песни MediaStore остались прежними.
- «На устройстве» — текущие треки, альбомы, исполнители, папки, очереди и визуализации.
- «Suno» — импорт лично выбранных аудиофайлов из официального экспорта Suno через системный Android OpenMultipleDocuments и сохранение URI-грантов. Треки слушаются в **существующем** Media3 ExoPlayer, с VU и другими визуализациями. Можно убрать документ из списка без удаления самого файла.
- «Яндекс Музыка» — честное сообщение, что каталог пока не подключён, и действующая ссылка на официальный сайт. Вкладка не просит у пользователя пароль или токен, не делает скрытых запросов и не утверждает, что стриминг работает.
- Suno также открывается через официальный сайт браузером; это не передача звука обратно в MARK Audio.

## Почему ограничено
Подписка Яндекс Музыки даёт доступ к сервису по его правилам, но не гарантирует стороннему приложению получение потоков. Документированный Yandex ID OAuth/PKCE позволяет войти в Яндекс ID, но этого недостаточно для чтения медиатеки и получения музыкальных URL. Неофициальные методы нельзя считать стабильным или разрешённым производственным контрактом.

У Suno на ноябрь 2026 не подтверждён общедоступный API для чтения библиотеки авторизованного пользователя и прослушивания потоков в стороннем плеере. На этом этапе импортируем разрешённые к использованию скачанные файлы, а не извлекаем сессионные cookie и не обходим DRM.

## План MARK Audio Music API
Наш независимый API / набор интерфейсов должен различать источники и возможности:
- MusicCatalog: `getLibrary`, `search`, `getPlaylists`.
- MusicAccess: `beginAuthorization`, `logout`, `capabilities`.
- MusicStream: `resolvePlayableMedia` — только при подтверждённом разрешённом потоке; иначе чёткая ошибка `NOT_SUPPORTED`.
- PlaybackService/Media3 остаётся единственным проигрывателем; никакого второго аудиодвижка.

Нужен доступный и согласованный Яндексом способ получения пользовательской музыкальной медиатеки и потоков, чтобы реализовать настоящий сетевой адаптер. Если для этого требуется отдельная партнёрская интеграция — запросить доступ. Для Suno аналогично. Регистрационные `client_id` и `redirect_uri` ещё не настроены: кнопок фиктивного «Войти» нет.

### Защита
- Без паролей и токенов в репозитории или URL журнала.
- При согласованном OAuth — системный браузер, PKCE, минимальные scope и хранение в Keystore.
- SAF-гранты на Suno — только выбор пользователя; удаление из вкладки не удаляет оригинальный файл.
- Не расширять разрешения для локального проигрывателя без явной необходимости.

## Следующие проходы
1. Проверить API/партнёрскую возможность для полноценного воспроизведения Яндекс Музыки.
2. После подтверждения доступа — подключить авторизацию, медиатеку и разрешённые потоки к Media3; добавить интеграционные тесты.
3. Аналогично проверить доступ для личной Suno-библиотеки. До этого сохранять рабочее воспроизведение экспортированных треков.
4. Протестировать на Huawei Pura 80 Ultra / EMUI 15, особенно документные URI после перезапуска и фоновое воспроизведение.

**Статус:** функциональные вкладки и импортированные Suno-файлы — часть текущего PR; сетевой стриминг обоих сервисов не готов и не имитируется.


## Итерация 2 — MARK Audio 0.7.16 (20.11.2026)

**Смартфон и референс:** Huawei Pura 80 Ultra / EMUI 15, экран 6,78", 2848 × 1276 физических пикселей (Huawei). На скриншотах 0.7.15 третий источник Suno обрезался справа.

**Исправлено:**
- Убрана горизонтальная прокрутка переключателя. Compose Row распределяет ширину между тремя равноширокими FilterChip; все три видимы одновременно.
- Высота каждой кнопки 60 dp; «На устройстве» и «Яндекс Музыка» разбиты на две строки. Используется доступная ширина в dp, а не фиксированное разрешение в пикселях.
- Сокращены чрезмерно длинные тексты экранов Yandex/Suno; технические подробности Яндекса можно раскрывать.
- Локальный плеер, пять визуальных аппаратов, ExoPlayer, PCM и MediaSession не изменены.

**Собственный Music API v1:**
- Типизированные доступные возможности источников; контракт удалённой медиатеки и разрешённого потока; явные ошибки при отсутствии доступа. Никаких фиктивных треков и потоков.
- Подготовлен и тестируется OAuth-PKCE для Яндекс ID: S256, случайный verifier, CSRF state, строгая проверка редиректа и срока 10 минут. Это **библиотечная основа**, а не действующий вход.
- До регистрации своего OAuth-приложения, проверки доступных scopes и получения подтверждённого API для Яндекс Музыки **не включаем** callback activity, обмен токена, сетевой стриминг.
- Suno в 2026 анонсировал исследование партнёрского API; сторонние сервисы «Suno API» не равны официальному API. Suno MCP для ИИ-клиентов также не означает доступ к аудиопотоку для Android-плеера. Пока работает импорт разрешённых MP3/WAV.
- Без новых Android permissions, чужих OAuth-клиентов, cookie-извлечения, DRM-обхода или секретов в APK.

**Проверки:** unit-тесты возможностей и PKCE, Android CI/lint, затем подписанный релиз из main. Системное масштабирование текста и фоновые сценарии требуется проверить на физическом Huawei.

**Далее:** зарегистрировать свой Yandex OAuth client_id, согласовать redirect_uri и разрешённые Music scopes / партнёрский доступ; только затем подключать сетевую авторизацию и каталог. Аналогично выяснить партнёрские возможности Suno, не добавляя генерацию музыки.

## Итерация 3 — MARK Audio 0.7.20, второй OAuth Music API (21.11.2026)

Проверка владельца: на скриншоте кабинета OAuth второго приложения видно «Использование API Яндекс Музыки» с scope **music:api-public**, Client ID **b050d96e5d604629810dac08d122c698** (публичный). Он независим от клиента LoginSDK **cfaacee8ff6d4941a5966d00c53a61de** / scope login:info. Скриншоты личного кабинета, логин и секреты не переносим в публичную историю.

Реализован официальный сценарий **для OAuth-приложений «Для доступа к API»**: https://oauth.yandex.ru/authorize с фиксированным redirect_uri=https://oauth.yandex.ru/verification_code, response_type=code, scope=music:api-public, PKCE S256, генератор SecureRandom, семизначный код в интерфейсе MARK Audio и локальный HTTPS обмен POST https://oauth.yandex.ru/token. Client secret не нужен. Верификатор и токен зашифрованы отдельным ключом Android Keystore (AES-GCM). Время жизни проверяется, scope валидируется, произвольные ошибки сервера и токены не выводятся. Сброс не нарушает LoginSDK.

Этот этап **не доказывает работу API музыкального каталога**. Он не вызывает api.music.yandex.net или закрытые streaming endpoints. MarkMusicApiV1 оставляет PERSONAL_CATALOG и REMOTE_STREAM недоступными, а ошибки API_NOT_GRANTED явными. Следующий этап — проверить условия и поддерживаемый интерфейс медиатеки/потоков с Яндексом; не считать наличие scope документированным контрактом доступа к музыке.

Проверка: unit-тесты PKCE/URL/формы, Gradle CI и signed release только после успешного CI. Отдельно протестировать на Huawei Pura 80 Ultra: получение кода, переход браузер → приложение, успешный и ошибочный обмен, перезапуск, локальное отключение, фоновый Media3 и отсутствие регрессий в Яндекс ID.

Источники OAuth: https://yandex.ru/dev/id/doc/ru/register-api ; https://yandex.ru/dev/id/doc/ru/codes/screen-code .

## Итерация 4 — MARK Audio 0.7.21: исправление фактического формата кода (21.11.2026)

На Huawei Pura 80 Ultra страница oauth.yandex.ru/verification_code показала **16-символьный код из латинских букв и цифр** при входе через второй зарегистрированный Music API OAuth-клиент. 0.7.20 ошибочно ограничивал ввод семью цифрами, из-за чего exchangeCode() вообще не вызывался.

Исправление 0.7.21: принимаем **16 латинских букв/цифр либо 7 цифр**, сохраняем регистр, отображаем буквенную клавиатуру, маскируем ввод по умолчанию и проверяем корректность до POST. Добавлены тесты на обе формы, длину, регистр и недопустимые символы. Ни реальный код со скриншота, ни личные данные владельца не попали в историю Git.

Официальный глоссарий Яндекс OAuth прямо определяет «Код для получения токена» как строку из **16 символов**: https://yandex.ru/dev/id/doc/ru/concepts/glossary . При этом действующая страница https://yandex.ru/dev/id/doc/ru/codes/screen-code всё ещё упоминает 7-значный код в пояснении ошибки bad_verification_code — формулировки документации не полностью согласованы. **Успешный обмен 16-символьного кода на токен пока не подтверждён** и должен быть протестирован на Huawei новым кодом; при ошибке bad_verification_code потребуется отдельно проверить соответствие типу приложения и способу OAuth, не обходя ограничения сервера. Scope music:api-public по-прежнему не равен подтверждённому контракту музыкального стриминга.

## Итерация 5 — MARK Audio 0.7.22, независимая проверка токена (21.11.2026)

Владелец подтвердил успешное получение отдельного OAuth-токена Music API на физическом Huawei Pura 80 Ultra в 0.7.21: карточка приложения показала «Отдельный OAuth-токен Яндекс Музыки получен», и штатный LoginSDK Яндекс ID остался подключённым. Скриншот и персональные данные не добавляются в GitHub.

Следующий безопасный шаг: кнопка «Проверить OAuth-токен» делает **только** документированный запрос к API Яндекс ID (`GET https://login.yandex.ru/info?format=json`, Authorization в HTTP-заголовке), проверяет `client_id` второго Music OAuth-приложения и наличие ID аккаунта. Токен извлекается из Android Keystore-хранилища только для запроса; пользовательские данные ответа не выводятся и не сохраняются. Отдельные ошибки для истёкшего, неверного, чужого или временно недоступного токена; сетевые ошибки не стирают токен. Источник: https://yandex.ru/dev/id/doc/ru/user-information .

Проверка НЕ означает наличие разрешённого Music catalog/streaming API. По состоянию на 21.11.2026 в официальных доступных материалах Яндекса не найдена публичная спецификация стороннего интерфейса для личной музыкальной библиотеки и потоков. Исследованные открытые клиенты (MarshalX/yandex-music-api) — reverse-engineering сообщества, а не официальное согласование. `MarkMusicApiV1` продолжает явно блокировать `PERSONAL_CATALOG` и `REMOTE_STREAM`. После прохождения CI/подписи требуется проверить кнопку на Huawei.

## Итерация 6 — MARK Audio 0.7.23, изолированный эксперимент Music API (21.11.2026)

**Результат предыдущего теста на Huawei Pura 80 Ultra:** в 0.7.22 пользователь нажал «Проверить OAuth-токен» и получил «Яндекс подтвердил токен этого Music API-клиента. Доступ к каталогу и потокам этим не проверяется». Следовательно, OAuth-проверка по официальному `login.yandex.ru/info` успешна. Скриншот и личные данные в репозиторий не переносим.

**Следующий узкий тест (только с прямого согласия пользователя через кнопку):** вызов `GET https://api.music.yandex.net/account/status` с токеном второго Music OAuth-клиента. Метод идентифицирован по открытой неофициальной документации сообщества https://github.com/MarshalX/yandex-music-api и https://github.com/isamarin/yam-api/blob/master/docs/yandex-api.md . Это не подтверждённый Яндексом публичный контракт API для сторонних приложений. Код не использует чужие Client ID/токены, не пытается получить контент или DRM-ключи, не следует редиректам, не показывает и не сохраняет пользовательские сведения из ответа. Неудачный ответ не уничтожает OAuth-токен и не нарушает LoginSDK.

**Проверяемое утверждение:** принимает ли конкретный endpoint `/account/status` OAuth-токен собственного зарегистрированного приложения с `music:api-public`. Результат HTTP 200 с `result.account.uid` классифицируется как ответ сервера, но **не означает** работу персональной библиотеки, права на лицензированное воспроизведение или возможность стриминга. Ошибки 401/403, странная схема, сеть/429 показываются обезличенно. Прежде чем переходить к плейлистам или потокам, требуется успешный опыт на Huawei и разъяснение правообладателя о допустимом использовании.

**Следующие проверки:** unit-тесты классификации, GitHub Actions, APK подписанный закреплённым сертификатом, затем пользовательская проверка кнопки на Huawei и регрессий локального Media3.
