# MARK Audio — технический аудит веб-версии Яндекс Музыки (22.11.2026)

## 1. Назначение и границы проверки

Проверить архитектурные причины, почему авторизация в официальном браузере позволяет слушать музыку, а выданные **собственным** OAuth-клиентам MARK Audio токены дают HTTP 403 на `GET https://api.music.yandex.net/account/status`. Найти технически воспроизводимый и допустимый путь интеграции на Huawei Pura 80 Ultra / EMUI 15.

**Метод:** официальные справки Яндекса и Android; чтение двух открытых независимых технических описаний веб-клиента; анализ существующих исходников MARK Audio и результатов аппаратных тестов #46. Нет доступной авторизованной сессии владельца в исследовательской среде, нет записи HAR/DevTools владельца. По прямому открытию `https://music.yandex.ru/` исследовательская среда получила региональную заглушку («not available in your region»). **Живой трафик авторизованной веб-версии самим MARK Audio не перехватывался и не воспроизводился.**

## 2. Проверено непосредственно

1. В MARK Audio 0.7.28 существуют три независимых собственных OAuth-подключения плюс основной Yandex ID. В тесте на Huawei оба музыкальных scopes (`music:api-public` и `music:major-public-api`) для API-type клиента `017187c1377846eb80cedcd93cf3fd38` не изменили результат `/account/status`: HTTP 403. Проверка `login.yandex.ru/info` подтверждает соответствие Client ID и user ID перед ручным запросом. Это вывод **только для этого метода**.
2. Официальный Yandex LoginSDK обеспечивает вход пользователя; OAuth-токен не подтверждает доступ к любому недокументированному API отдельного сервиса.
3. Android `WebView` может показывать современное JavaScript-веб-приложение, но у него отдельное от внешнего браузера хранилище сессии; Android не предоставляет браузерные cookies чужого приложения нашему WebView. См. https://developer.android.com/develop/ui/views/layout/webapps/webview (разделы о JavaScript, навигации, безопасности).
4. Веб-страница Яндекс Музыки на официальном домене действительно существует, но региональные/сессионные ограничения могут делать её недоступной в конкретной среде. Нельзя считать поддержку Huawei WebView доказанной без теста на устройстве.

## 3. Независимые исследования веб-архитектуры: не официальный контракт

### Проект isamarin/yam-api

Источник: https://github.com/isamarin/yam-api/blob/master/docs/yandex-api.md (заявленные автором живые пробы 16.07.2026).

- Сообщает, что современные JSON-метаданные/поиск/плейлисты обращаются к `https://api.music.yandex.net`.
- Описывает `/search`, `/users/{uid}/playlists/list`, `/users/{uid}/likes/tracks` и другие операции.
- Автор испытывал действующий OAuth-токен **от другого Client ID** и получил 200 на `/account/status`; это не доказательство, что наш собственный Client ID имеет доступ.
- Наблюдения автора о cookies и качестве воспроизведения основаны на его сессии и не переносятся на другие аккаунты/страны/клиенты.

### Проект fgsfds1/yt-dlp-yandex-music-plugin

Источник: https://github.com/fgsfds1/yt-dlp-yandex-music-plugin/blob/master/research/api-notes.md (исследование фронтенда версии `music/v4.1520.1` от 17.08.2026, отдельные дополнения сентября 2026).

- Указывает тот же современный хост `api.music.yandex.ru`; описывает как JSON API, так и Next.js/RSC-предзагрузку на страницах плейлистов.
- Утверждает, что старые `/handlers/*.jsx` устарели. Значит, слепой перенос старых рецептов API не годится.
- Описывает браузерные сессионные cookies, набор заголовков, региональные и пользовательские настройки, различия между метаданными и доставкой аудио.
- Часть публикации посвящена обходным схемам получения и декодирования потоков. **В MARK Audio не переносим ключи, извлечённые из JS-бандлов, подписи для закрытых URL, чужие Client ID/сессионные cookies или способы обхода защиты аудио.**
- Описанные заголовки и поля — зафиксированное поведение на дату исследования, не документированное разрешение для другого приложения.

**Важно:** утверждения двух независимых проектов о заголовках и cookie-авторизации частично расходятся; поэтому нельзя назвать один отсутствующий заголовок причиной 403. Серверные правила entitlement/Client ID/сервиса не опубликованы.

## 4. Модель браузерной авторизации против нашего OAuth

| Уровень | Веб-сервис music.yandex.ru | MARK Audio 0.7.28 |
|---|---|---|
| Вход пользователя | Собственный браузерный session flow Яндекса | Официальный Yandex LoginSDK + отдельный OAuth PKCE |
| Идентичность веб-приложения | Официальный сайт/его сессия/серверная конфигурация | Наш собственный публичный Client ID |
| Доступ к данным | Непосредственно определяется серверными правилами Яндекс Музыки | `login.yandex.ru/info` подтверждает только личность/клиента |
| Проверка Music API | При реальном веб-использовании сайт обслуживает разрешённые запросы | Наши попытки `/account/status` дали 403 |
| Получение музыки | Официальная лицензированная веб-среда и её воспроизводитель | Media3 есть, но нет подтверждённого разрешённого stream contract |

**Причина 403 остаётся неизвестной**. Гипотезы — регистрация приложения/серверное одобрение, особенности запроса, подписки, региона. Гипотеза != факт.

## 5. Что реально можно предпринять

**Маршрут A — официальный сайт в MARK Audio.** Проверить на Huawei изолированный полноэкранный WebView, открывающий только `https://music.yandex.ru/`. Он должен:
- показывать сам официальный сайт, без выдачи своего интерфейса за Яндекс Музыку;
- не извлекать и не экспортировать cookies/токены/аудио, не делать `shouldInterceptRequest` с приватными данными и не применять JS-инъекции;
- не добавлять `addJavascriptInterface` для чужих страниц, не отключать TLS-проверки;
- соблюдать безопасную навигацию, HTTPS, системный Back, пользовательский выход;
- **не заменять рабочие Music OAuth и Media3**;
- проверить: отображение страницы, авторизацию, плейлист, поиск, воспроизведение, уход в фон/возврат, звук при блокировке экрана, энергосбережение EMUI; отдельно проверить политику сайта относительно встраивания и DRM.

Это **тест возможности**, не обещание, что сайт позволит embedded WebView. Сессии внешнего браузера и WebView различны: встраивание может потребовать отдельного входа. Другой безопасный fallback — открывать официальный сайт в системном браузере/Custom Tab.

**Маршрут B — нативная интеграция.** Оформить вопрос Яндексу: официальный base URL, перечень операций read-only (плейлисты/лайки/поиск), scopes, тип регистрации, allowlisting, спецификация потоков/DRM и права встраивания сайта. Пока такой контракт отсутствует, не переносить закрытые endpoints из обратной разработки в production.

**Маршрут C — пользовательские экспортированные данные.** При наличии подходящих официальных метаданных возможен локальный SAF-импорт без музыкальных потоков. Схема архива пока не подтверждена.

## 6. Практический следующий этап

1. Отдельная экспериментальная **веб-панель** без замены текущего источника «Яндекс Музыка»: открыть оригинальный сайт в безопасном WebView и альтернативно в системном браузере. Тестовая сборка — только после code review, unit tests/Lint/подписи.
2. На Huawei сообщить лишь обезличенную матрицу: страница открылась? логин работает? каталог отображается? трек воспроизводится? продолжает ли звук в фоне? Не передавать HAR, cookies, пароли и токены.
3. Если WebView исправно отображает официальный сайт и соответствует правилам сервиса — можно использовать как отдельный способ прослушивания внутри MARK Audio, **без присвоения лицензированных потоков Media3**.
4. Если WebView заблокирован сервисом/географией/DRM — не обходить ограничение, сохранить внешний браузер и добиваться официального API.

## Вердикт

**Не найдено доказательства, что наличие собственной OAuth-авторизации даёт стороннему приложению все права официальной веб-версии. Найдены конкретные технические свидетельства современной веб-архитектуры, но они не являются готовым официальным SDK или лицензией.** Наиболее безопасный следующий технический эксперимент — изолированное отображение официальной веб-версии в WebView на реальном Huawei, не перехватывая её трафик и не копируя закрытые механизмы.
