# MARK Audio × Яндекс Музыка — проверка доступа к каталогу (21.11.2026)

## Статус

**ПОДКЛЮЧЕНИЕ ЛИЧНОГО КАТАЛОГА И АУДИОПОТОКОВ: ОЖИДАНИЕ ОФИЦИАЛЬНОГО КОНТРАКТА/РАЗРЕШЕНИЯ.**

Тестирование на реальном Huawei Pura 80 Ultra / EMUI 15 в версиях MARK Audio 0.7.19–0.7.25 подтвердило:

| Действие | Результат | Что это доказывает |
|---|---|---|
| Яндекс ID, Android LoginSDK | Успешно | Вход пользователя работает |
| Отдельный Music OAuth `music:api-public` | Код подтверждения успешно обменян | У собственного OAuth-клиента есть выданный токен |
| `GET https://login.yandex.ru/info?format=json` | Успешно, совпал `client_id` | Яндекс ID подтверждает действительность токена и принадлежность приложению |
| `GET https://api.music.yandex.net/account/status` | **HTTP 403** | Конкретный сервер Music API запрещает выполнение этого запроса нашим токеном/клиентом |
| Личная медиатека / плейлисты / streams | **Не проверены и не включены** | 403 на статусе не доказывает доступность или недоступность всех остальных операций |

Тестовый Music endpoint взят из **неофициальной** документации сообщества, а не из публикации Яндекса для сторонних Android-плееров. В MARK Audio он используется только по нажатию кнопки. После однозначного HTTP 403 регулярное повторение запроса не требуется.

## Результаты исследования официальных материалов

1. Яндекс разделяет OAuth-приложения на «Для авторизации пользователей» и «Для доступа к API». Для второго типа в официальном описании указано, что он работает только с данными разработчика; тип нельзя изменить после создания.
   https://yandex.ru/dev/id/doc/ru/register-client
2. Регистрация клиента для доступа к API сама по себе не описывает поддерживаемые методы музыкального сервиса: Яндекс предписывает использовать **документацию самого сервиса**.
   https://yandex.ru/dev/id/doc/ru/register-api
3. В условиях API Яндекс ID сказано, что использование API других сервисов осуществляется по условиям **соответствующего** API.
   https://yandex.ru/legal/authid_api/ru/
4. Условия Яндекс Музыки закрепляют права на музыку и сервисную базу данных за правообладателями/Яндексом; отдельные технические и юридические ограничения возможны.
   https://yandex.ru/legal/music_termsofuse/ru
5. Обнаружен сторонний проект `MarshalX/yandex-music-api`, который описывает многие операции через обратную разработку, **но не устанавливает договорную поддержку или доступ стороннему Client ID**. В FAQ по получению токена автор прямо отмечает ограничения на создание собственного OAuth-приложения для этих методов.
   https://github.com/MarshalX/yandex-music-api
   https://ym.marshal.dev/token/
6. Официальная поддержка разработчиков Яндекс OAuth просит описать проблему и указать `Client ID`. Также доступна форма поддержки Яндекс Музыки.
   https://yandex.ru/support/id/ru/troubleshooting/passportapi
   https://yandex.ru/support/music/ru/write-to-support

**Вывод:** Отдельный OAuth-токен можно получить и проверить, но нет подтверждённого опубликованного соглашения/эндпоинтов, которые дают именно нашему приложению право читать коллекцию, получать search/playlists или аудиопотоки. Нельзя на основании одного scope обещать нативный стриминг, подменять client ID чужим, использовать сессионные cookie/скрытые заголовки для обхода HTTP 403, массово опрашивать закрытые методы или копировать DRM-контент.

## Запрос к Яндексу, который необходимо отправить от владельца приложения

Тема: **Доступ собственного OAuth-клиента к API каталога Яндекс Музыки — MARK Audio, HTTP 403**

Здравствуйте!

Разрабатываю персональное Android-приложение MARK Audio (`com.markmusic.player`, Huawei / Android, Kotlin/Media3). Я зарегистрировал собственное OAuth-приложение типа «Для доступа к API» с публичным Client ID `b050d96e5d604629810dac08d122c698` и разрешением `music:api-public`.

Официальный OAuth flow успешно выдаёт токен. API Яндекс ID `GET https://login.yandex.ru/info?format=json` подтверждает этот токен и правильный Client ID. Однако один тестовый read-only запрос `GET https://api.music.yandex.net/account/status` отвечает **HTTP 403 Forbidden**. Данный Music URL известен из неофициальных реализаций; возможно, он не предназначен для сторонних клиентов.

Подскажите, пожалуйста:

1. Предусмотрен ли сейчас официальный API/SDK для стороннего Android-приложения, позволяющий читать собственную библиотеку пользователя («Мне нравится», личные плейлисты), выполнять поиск и получать карточки треков/альбомов?
2. Какой тип OAuth-приложения и какие scopes нужны для таких операций? Применимо ли разрешение `music:api-public` именно к этой задаче?
3. Существуют ли опубликованные URL, спецификация ответов, лимиты и процедура подключения/одобрения независимого клиента? Если требуется партнёрская заявка, куда её направлять?
4. Возможен ли разрешённый стриминг по подписке в собственном нативном плеере (Media3), и, если да, каким SDK и способом соблюдения прав/DRM следует пользоваться?
5. Если доступ к каталогу через API сторонним приложениям не предоставляется, разрешён ли импорт **метаданных** личной коллекции из официального архива данных Яндекс ID и каков его машиночитаемый формат?

Токен, коды подтверждения, Client secret, данные аккаунта и пароли к архиву не прикладываю. При необходимости готов предоставить обезличенные диагностические сведения.

Спасибо!

## Параллельный законный путь: экспорт личных данных

В официальной справке Яндекс ID описан заказ архива данных выбранного сервиса:
https://yandex.ru/support/id/ru/personal-data.html

Это может позволить пользователю **вручную перенести метаданные** коллекции в MARK Audio без обращения к заблокированному Music endpoint. Однако официальная справка **не гарантирует**, что архив именно Яндекс Музыки включает полные списки треков или пригодные JSON/CSV-таблицы. Пока схема архива не проверена, **не пишем выдуманный JSON-парсер** и не просим передавать в репозиторий ZIP с приватными данными.

Безопасная последовательность:
1. Владелец локально заказывает архив сервиса «Музыка» (если он доступен в списке), получает его и распаковывает у себя на устройстве или компьютере.
2. Сначала проверяется только список имён файлов и их расширений, **без содержания, токенов и личных данных**; если будут нужные плейлисты, используется обезличенный образец нескольких записей с заменой имён/ID.
3. После установления реального формата разрабатываем **локальный офлайн-импорт метаданных** через Android Storage Access Framework, без загрузки ZIP на наш сервер и без доступа к лицензированным аудиофайлам.
4. Отображение названий в MARK Audio не должно создавать ложное впечатление, что трек доступен для воспроизведения: по нажатию можно открыть официальное приложение Яндекс Музыки, если известна допустимая публичная ссылка.

## Критерии следующего этапа разработки

**Если Яндекс разрешит API каталога:** на основе полученной спецификации и условий реализации создать минимальный `RemoteMusicGateway` для **одного** read-only разрешённого метода личной библиотеки; затем добавить тесты схем, обработку ошибок, кеширование без токенов в логах, контроль токена и реальный тест Huawei. Поиск/плейлисты добавлять по мере подтверждения. Streaming только после отдельного разрешения и технической спецификации.

**Если разрешён только экспорт метаданных:** реализовать импорт подтверждённого архивного формата, источник «Яндекс Музыка — импортированные сведения» и официальные ссылки для прослушивания. Не обещать Media3 для лицензированных треков.

**Если ни то ни другое недоступно:** сохранять работающий официальный вход и переход в сервис Яндекса, не вводить ложную поддержку каталога. Вопрос партнёрского доступа оставлять открытым в GitHub Issue #46.
