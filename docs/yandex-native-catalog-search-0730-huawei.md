# MARK Audio 0.7.30 — нативная проверка поиска Яндекс Музыки

## Цель и ограничение
По прямому требованию владельца: **без WebView в качестве музыкального каталога**. Новая версия удаляет встроенный веб-экран 0.7.29 и даёт одну реальную, ручную, нативную проверку метода поиска `GET /search?text=...&type=track&page=0`, описанного неофициальными SDK.

До аппаратной проверки **нет доказательства**, что собственные OAuth-клиенты MARK Audio имеют доступ к этому методу. Не выдавать новую кнопку за полнофункциональный каталог. Если сервер отклоняет запрос (403), это явный запрет только данного метода с данным токеном.

## Реализация
- Kotlin `YandexNativeCatalogGateway` реализует `MusicCatalogGateway.search`, но `likedTracks`, `playlists`, `tracks` пока возвращают `NOT_CONFIGURED`, не выдавая пустых фиктивных списков.
- Варианты собственного OAuth токена: пользовательский OAuth (`user_token` / `YandexMusicUserOAuthRules.CLIENT_ID`) и Music Major (`major_token` / `017187c1377846eb80cedcd93cf3fd38`). Ни один сторонний идентификатор не используется.
- Токены берутся непосредственно из старого локального Android Keystore AES-GCM vault, не отображаются и не копируются в другую базу.
- **Перед каждым запросом** `login.yandex.ru/info?format=json` проверяет Client ID и UID, сравнивая их с уже подключённым Yandex ID. Несовпадение не допускает Music API-вызов.
- После нажатия «Проверить нативный поиск» выполняется один GET `api.music.yandex.net/search` с `Authorization: OAuth <token>`. Нет повторных попыток, чужих cookies, подмены заголовков официального клиента, JSONP, DRM-обхода и аудиозагрузки.
- При HTTP 200 читаются только метаданные до 512 КБ: заголовки треков, артисты, ID, обложки, продолжительность. `canPlay=false` независимо от поля `available` сервера. Ничего не записывается на диск, не синхронизируется с Media3.
- При HTTP 401/403/429 отображаются явные сообщения об авторизации, отказе доступа или лимите.
- На главном экране Яндекс Музыки кнопка нативного поиска, а прежние экспериментальные OAuth-панели убраны под сворачиваемое «Техническая диагностика OAuth». Исправлена прежняя ошибочная ориентация на встраивание сайта.

## Проверка на Huawei Pura 80 Ultra / EMUI 15
1. Установить **подписанный** релиз 0.7.30 (после успешного CI и Signed Release) поверх прежней версии, не очищая данные.
2. Перейти в **Медиатека → Яндекс Музыка → Нативный каталог · поиск**.
3. Убедиться, что основной Яндекс ID подключён. Выбрать пользовательский OAuth и ввести название одного трека либо исполнителя.
4. Нажать **«Проверить нативный поиск»** только один раз и зафиксировать обезличенный итог: реальные карточки треков или HTTP 403/401/429/ошибка формата.
5. Если первый собственный клиент не получил каталог и Music Major уже подключён, выбрать Music Major и проверить один раз.
6. Не передавать в чат Client Secret, access token, refresh token, коды авторизации, cookie, HAR браузера, реальные private ID аккаунта.
7. При 403 **не пытаться обходить** его через сторонний Client ID или чужие заголовки; для production получить опубликованную спецификацию / поддержку Яндекса.

## Известные ограничения
- Поиск сейчас **экспериментальный, нативный, read-only**, не встроенный браузер.
- Яндекс Music метод не гарантирован для сторонних клиентов. Нет подтверждения на реальном Huawei до скриншота ответа.
- Избранное, плейлисты, потоковое воспроизведение и «Моя волна» через собственный Music API не подключены и не должны показываться как рабочие.
- Чтобы реализовать настоящий каталог, нужен разрешённый сервером API. Подписка и валидный OAuth этого не гарантируют.
